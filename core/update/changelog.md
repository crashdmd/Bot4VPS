## 5.0.0

# 🔐 Bot4VPS v5.0 — Безопасность, HTTPS и консольное меню

> **Панель умеет работать по HTTPS, секреты и резервные копии можно шифровать, вход защищается двухфакторной аутентификацией, а управлять установкой можно прямо с сервера через консольное меню.**

### 🔒 HTTPS для панели (модель 3x-ui)

- **Режимы**: off (как раньше), Let's Encrypt (certbot standalone, домен + e-mail), Self-signed (генерация на месте), Свой сертификат (внешние пути — без копирования — или загрузка файлов в Web), За прокси (доверенные IP/CIDR для X-Forwarded-Proto)
- Управление из Web (карточка «Сеть и доступ» в Настройках — порт и HTTPS в одном месте) и CLI (Безопасность → HTTPS сертификат); install.sh спрашивает про HTTPS при установке
- Перевыпуск кнопкой/пунктом меню; фоновое автопродление Let's Encrypt раз в сутки (обычный `certbot renew`, перезапуск панели только если сертификат реально обновился)
- Смена сертификата идёт через detached-раннер с health-check и автоматическим откатом на HTTP при неудачном старте — панель не «зависает» в сломанном состоянии
- Кука сессии помечается Secure в HTTPS-режимах; схема определяется по systemd-юниту — единственному источнику правды
- Просрочка и дни действия сертификата видны в UI и CLI; предупреждение при рассинхроне «режим задан, панель работает без HTTPS»

### 🖥️ Консольное меню (CLI)

- Новая команда `bot4vps` на самом сервере (создаётся сервисом при старте; аналогично `python3 -m ui.cli`): статус, включение/выключение Web и смена порта, HTTPS-сертификат, настройка Telegram, перезапуск, обновление, журнал, удаление сервиса
- Раздел «Восстановление» — доверенный root-канал для починки панели, когда Web недоступен: диагностика, восстановление config.json из копии, восстановление Bot4VPS из архива, сброс конфигурации, перевыпуск кода первичной установки, аварийный сброс пароля Web и 2FA
- Управление мастер-ключом шифрования: состояние и «показать» (консоль — всегда доступный аварийный путь)

### 🔑 Шифрование секретов и мастер-ключ

- Пароли серверов, sudo и Telegram Bot Token шифруются на диске (значения с префиксом `enc1:` в `servers.json` / `config.json`); ключ — `keys/secret.key` (создаётся автоматически, права 0600)
- Карточка «Мастер-ключ» в Настройках → Безопасность: состояние ключа, кнопка «Зашифровать все секреты» (сканер всего ядра), восстановление при утере — ввести сохранённый ключ (данные сохранятся) или создать новый, тогда старые enc1: значения безвозвратно теряются и очищаются; просмотр значения строго после подтверждения — 2FA приоритетно, код в Telegram запасной, консоль — аварийный путь
- Инвариант ключа: если ключ не расшифровывает данные, панель не работает «вполсилы» — запускается явный recovery-флоу

### 💾 Backup: шифрование архивов и self-restore

- Опциональное шифрование архивов паролем (AES-256-GCM, формат B4VE) для копий установки Bot4VPS и серверных профилей; пароль требуется при просмотре, восстановлении и импорте
- «Забыл пароль» архива — сброс через подтверждение (2FA / код в Telegram / консоль)
- Self-restore: восстановление самой установки Bot4VPS из полного архива прямо из Web — операция идёт detached-раннером, переживает перезапуск панели (новый процесс подхватывает идущую операцию), с защитной копией и проверкой результата
- Копия установки корректно упаковывает каталог с локальным git-клоном (hardlinks больше не ломают архив)

### 🔥 Firewall: переключение бэкендов и стабильность

- Переключение UFW ↔ firewalld ↔ nftables с переносом правил: инвентарь обеих сторон, подтверждение переносимых портов, точный reconcile, откат при неудаче
- Автоматический провижининг базовой nftables-таблицы `bot4vps` и самовосстановление после устаревшего owned-токена (switch-away + reboot)
- Переключение на неустановленный target больше не теряет правила source — переносятся все правила, включая порт панели

### 🧭 Вход и первый запуск

- Новый экран входа: без интерфейса-обёртки, три темы, работает даже до завершения настройки
- Первый вход — по одноразовому коду первичной установки (выдаёт установщик, действует 10 минут, перевыпуск из CLI), затем мастер создаёт логин и пароль администратора
- Двухфакторная аутентификация Web (TOTP): QR-код из панели, recovery-код не обходит 2FA, аварийный сброс из консоли
- Двухфазное восстановление пароля: код в Telegram + собственный новый пароль
- Отключение защиты входа — подтверждённая операция: старый пароль + код 2FA (или код в Telegram, когда 2FA не включена); если второго фактора нет, подтверждением служит сам пароль. Смена пароля панели при выключенной защите тоже требует старый пароль — открытую панель больше нельзя угнать, задав свой пароль и включив защиту. Включение защиты сбрасывает текущую сессию — вход только заново, с паролем

### 🛡️ Защита от брутфорса

- Первый шаг входа ограничен: 10 неудачных попыток с одного адреса за 15 минут → 429 с Retry-After; успех сбрасывает счётчик

### 🐛 Исправления

- Установка: генерация кода первичной установки больше не гасит установку на чистой машине (SIGPIPE 141 под `set -o pipefail`); поиск certbot не загрязняет stdout; панель честно ждёт готовности после старта (до 15 с)
- Web: API создания сервера больше не возвращает пароль в ответе
- Firewall: классификация IPv6-цепочек ufw (`ufw6-*`) — switch ufw→nftables больше не обрывается; честная ошибка при неудачной подготовке target вместо `rollback_unverified`; деактивация source синхронизирует persistence — bypass-правило не «выигрывает лотерею» после reboot
- Backup: web-driven self-restore не оставляет операцию «failed» при перезапуске панели в середине операции; verify не падает на изолированных записях каталога (тройная проверка: tar exit 0 + карантин + отсутствие архива в storage)
- Backup: удалено мёртвое поле `automatic.timezone` — расписание всегда считается по локальному времени сервера, поле вводило в заблуждение в API (легаси-конфиги вычищаются автоматически)

### 🛠️ Прочее

- Все ошибки HTTPS (занятый порт 80, DNS, лимиты Let's Encrypt, кривая пара сертификат/ключ) — с объяснением и подсказкой, что делать
- Health-check апдейтера, self-restore и смены порта понимают HTTPS-схему панели
- Фирменные иконки Docker и WireGuard в Web UI

## 4.7.0

# 🚀 Bot4VPS v4.7

### 🛠 Quick Setup

> **Раздел быстрой настройки сервера вырос в полноценный центр администрирования.**

- **SSH и доступ** — менеджер SSH-ключей per-user, реестр занятости ключей между серверами, безопасное отключение password-auth с переключением на ключ, смена паролей и пользователей, смена SSH-порта (с учётом systemd socket activation), работа без sudo: набор доступных действий строится по фактическим правам
- **Firewall** — управление UFW, firewalld и nftables: правила с протоколом ANY и Source IP/CIDR, установка, отключение и удаление
- **Пакеты** — каталог популярных утилит и сервисов по категориям с пакетной установкой
- **Система и диагностика** — часы, hostname, swap, fail2ban

### 📡 Мониторинг доступности

- Новый критерий доступности: ICMP → SSH-порт → 80 → 443 — закрытые серверы без ICMP/80/443 корректно считаются доступными
- Ошибка SSH-авторизации больше не переводит сервер в Offline — отображается отдельным статусом
- Кнопка «Проверить доступность» в Web и Telegram — быстрый параллельный сетевой чек вместо полного SSH-прогона
- Новый сервер при создании сразу получает статус Online/Offline
- При открытой панели статусы обновляются автоматически

### 🖥️ Web UI

- SSH-терминал: исправлена геометрия окна — последняя строка больше не уходит за пределы терминала
- Список «Файлы → Ключи» показывает только SSH-ключи, без служебных файлов реестра
- История задач отсортирована по времени создания

### 🏗️ Архитектура

- Фоновые задачи мониторинга (System Sync, Availability, SSL, обновления) принадлежат ядру и работают при любом варианте установки — включая выключенный Telegram
- Системный SSH-сбор каждые 15 минут выполняется молча, без уведомлений; уведомления о доступности — отдельная настраиваемая задача

## 4.1.0

# 🚀 Bot4VPS v4.1.0


### 📋 История задач
- Добавлена **постоянная история задач** с сохранением после перезапуска Bot4VPS.
- История задач теперь хранится отдельно от журнала уведомлений.
- Добавлено удаление отдельных записей и полная очистка истории.
- История автоматически обновляется в Web UI без перезагрузки страницы.
- Большие карточки истории заменены на компактную таблицу.
- Полный лог задачи вынесен в отдельное окно просмотра.

### 🔔 Уведомления
- Внешний вид уведомлений приведён к **компактной форме**.
- В уведомлениях добавлена кнопка **📜 Посмотреть лог** для завершённых задач.
- Кнопка просмотра лога отображается только если задача сохранилась в истории и её лог доступен.

### ⚙️ Task Manager
- Убраны лишние события о создании и начале выполнения задач.
- Событие `queued` теперь создаётся только при реальном ожидании задачи в очереди.
- Уведомления о состоянии задач приведены к более понятной модели:
  - ⏳ ожидание;
  - ✅ успешное завершение;
  - ❌ ошибка;
  - ⚠️ отмена;
  - ⏸️ пауза очереди.
- Исправлено отображение событий задач в Web UI.

### 🐳 Docker & 🔒 WireGuard
- Исправлена навигация после удаления сервисов.
- WireGuard теперь корректно возвращает пользователя туда, откуда была открыта панель:
  - из списка → обратно в список WireGuard;
  - со страницы сервера → обратно на страницу сервера.
- Исправлено дублирование кнопок в блоке **«Быстрые действия»**.
- Устранены проблемы с конкурентными обновлениями Quick Actions.
- Исправлена синхронизация состояния frontend-модулей Docker и WireGuard.

### 🖥️ Web UI
- Унифицирована загрузка stateful ES-модулей.
- Устранена возможность создания нескольких экземпляров одного frontend-модуля из-за различающихся versioned URL.
- Улучшена синхронизация состояния интерфейса после изменения сервисов и выполнения задач.

### 🛡️ Надёжность
- Добавлено безопасное постоянное хранение истории задач.
- Предусмотрена защита от конфликтов при одновременном изменении истории Task Manager и Web UI.
- История задач и журнал уведомлений работают независимо и больше не влияют друг на друга.
