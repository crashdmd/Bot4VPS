## 6.0.0

# 🌐 Bot4VPS v6.0 — 3x-ui и развитие управления сервисами

> **Bot4VPS получил встроенное сопровождение 3x-ui: установка и управление панелью Xray. Web и Telegram используют общий сервисный слой, а операции Docker и списки сервисов стали информативнее и удобнее на мобильных устройствах.**

### 🌐 3x-ui

- Новый сервис **3x-ui** для установки, обновления и удаления панели управления Xray; состояния установленных панелей синхронизируются в общий сервисный кэш, а релизные артефакты кэшируются для повторного использования
- Карточка 3x-ui в Web UI: состояние systemd-сервиса и автозагрузки, версия, адрес панели, запуск/остановка/рестарт, логи и выбор версии обновления
- Управление учётной записью панели, портом и web base path; при смене порта открывается новый порт панели и закрывается прежний, когда это требуется
- Поддержка BBR и обновления `geoip.dat` / `geosite.dat`; после обновления geo-файлов панель перезапускается, чтобы применить новые данные
- Установка и выпуск сертификата Let's Encrypt для домена через acme.sh, а также shortlived-сертификата для IP; сертификат может сразу назначаться панели. Управляемые сертификаты отображаются, принудительно продлеваются и удаляются, а пути сертификата панели очищаются, если удалённый сертификат использовался ею
- Перед standalone-выпуском сертификата Bot4VPS временно подготавливает HTTP-порт и возвращает изменённое состояние после операции; состояние firewall и systemd-сервисов не остаётся изменённым из-за самого выпуска
- Экспорт базы 3x-ui создаёт согласованную SQLite-копию; импорт `.db` и `.dump` проверяет целостность, сохраняет предыдущую базу, выполняет миграцию и возвращает панель в работу
- **SelfSNI** создаёт и обслуживает сайт для 3x-ui: проверяет DNS домена, развёртывает nginx с сертификатом Let's Encrypt, назначает его панели и показывает параметры Reality для настройки инбаунда. При удалении очищаются состояние сайта и SSL-мониторинг этого домена

### ⚙️ Общие сервисы и Web UI

- Появилась общая фоновая проверка сервисов: все установленные сервисы одного сервера синхронизируются через одно SSH-подключение, а интерфейсы читают общий актуальный кэш
- Docker показывает живой прогресс загрузки образов, позволяет отменить выполняющуюся загрузку и открыть результат после завершения
- Списки серверов WireGuard, Docker и 3x-ui приведены к общему табличному виду, показывают актуальные статусы и корректно блокируют операции для недоступного SSH-порта
- Обновлены мобильные раскладки сервисов, модальное представление задач, фильтрация статусов и отображение фоновых операций
- Доменные имена серверов резолвятся через публичную цепочку DNS для мониторинга и отображения IP-адреса

### 🤖 Telegram

- Добавлен интерфейс 3x-ui в меню «Задачи» и в карточку сервисов сервера. Он маршрутизирует пользователя к тем же публичным операциям сервисного слоя: управление сервисом и панелью, сертификаты, BBR, geo-файлы, SelfSNI, экспорт/импорт базы и удаление
- Переходы сохраняют исходную точку: из карточки сервера пользователь возвращается к сервисам этого сервера, из «Задач» — к списку 3x-ui. Это же правило действует для вложенных экранов, ввода, загрузки базы и результатов фоновых задач
- Импорт базы в Telegram принимает только непустые `.db` и `.dump` размером до 5 МиБ, использует сгенерированное временное имя и передаёт файл существующей очереди операций

## 5.2.0

# 🔐 Bot4VPS v5.2 — Hardening SSH и большой апгрейд Telegram

> **Панель сверяет SSH host key каждого сервера до отправки пароля, Telegram-интерфейс прошёл полный аудит и рефакторинг (безопасность, отзывчивость, уведомления), а события приходят сами — одним окном-сводкой вместо потока сообщений, без нажатия кнопок.**

### 🛡 Верификация SSH host key

- Каждое SSH-подключение панели (Quick Setup, мониторинг, бэкапы, терминал, восстановление) сверяет host key сервера с сохранённым — **до отправки пароля**: подмена сервера (MITM) больше не даёт перехватить учётные данные
- Записи нет → ключ принимается и закрепляется при первом подключении (TOFU); сохраняются тип ключа, сам ключ и отпечаток SHA256 в формате OpenSSH
- Ключ не совпал (сервер переустановили?) → подключение блокируется, в журнал уходит CRITICAL-событие с обоими отпечатками (одно на сервер — без спама от фонового мониторинга)
- Принять ключ переустановленного сервера можно из Quick Setup → SSH / Доступ или из CLI → Безопасность; в Telegram — прямо из карточки сервера (см. блок Telegram ниже)
- Слой встроен в единую точку подключения (`create_ssh_client`) — все 70+ потребителей ядра защищены автоматически, CAS-механизмы Quick Setup не затронуты

### 🔑 Пароли

- Минимальная длина НОВЫХ паролей — 10 символов: панель (создание админа, смена, восстановление) и серверы (смена пароля, новые пользователи, переключение пользователя)
- Существующие пароли короче минимума остаются валидными — вход не ломается, политика касается только создания и смены

### 🧹 Утечки секрета

- Из кода убран литерал предсказуемого секретного ключа сессии (аварийный режим получает случайный per-boot ключ)
- При переустановке панели с существующим мастер-ключом оставшиеся открытые секреты шифруются сразу, а не ждут ручного «Зашифровать все секреты»

### 🛠 Установка

- Токен Telegram проверяется реальным getMe до признания установки успешной: явный отказ авторизации — переспрос токена, сетевая недоступность — только предупреждение, установку не блокирует
- Quick Setup корректно обрабатывает host-key поля при недоступном SSH и экспортирует действие принятия ключа

### 📜 Обновления и откат

- Кнопка «История версий» переименована в «Описание версии» и показывает описание **установленной** версии: источником служит changelog из состава кода, а не локальный кэш, который мог оставаться от предыдущей версии
- В списке версий отката у каждой версии появилась кнопка «описание» — секция из changelog
- Подтверждение отката говорит правду о границе: откатиться можно на версии 3.0 и новее (минимальная версия с Web UI; само ядро обновлений и отката появилось только в 4.0), более старые версии устанавливаются вручную через консоль — раньше два сообщения противоречили друг другу, называя 3.0 и 4.0

### 🤖 Telegram

Полный аудит Telegram-интерфейса и его рефакторинг: безопасность, отзывчивость, уведомления и больше двадцати закрытых находок.

#### 🔒 Безопасность

- Доставка накопленных уведомлений и текстовые команды бота доступны только авторизованным пользователям — раньше очередь событий мог дёрнуть любой, знающий бота
- Имена SSH-ключей в Telegram валидируются: обход пути (`../`) и служебные файлы (мастер-ключ шифрования, реестр ключей) недоступны из интерфейса бота
- Карточка события в журнале экранирует HTML — спецсимволы в сообщениях больше не ломают просмотр
- Telegram Bot Token больше не попадает в журнал: исключения библиотеки маскируются до записи (InvalidToken, NetworkError с URL API)

#### 🔔 Уведомления

- Доставкой владеет фоновая задача панели: события приходят сами в течение нескольких секунд — без нажатия кнопок и без «догоняющих» сообщений после переходов по меню. Backlog простоя или рестарта доставляется тем же фоном при старте
- Несколько событий, случившихся подряд, приходят **одним окном-сводкой** — «📬 Уведомления: N» со счётчиками по уровням (Критические / Обратить внимание / Информационные) — вместо отдельных сообщений на каждое
- Непрочитанное уведомление **аккумулируется**: пока вы его не открыли, новые события не плодят отдельные сообщения, а дополняют ту же сводку — живое сообщение обновляется на месте
- **Статус «прочитано» единый с Web.** Доставка сама по себе ничего не помечает: событие гаснет, когда вы его прочитали — открыли карточку, нажали «✅ Прочитано» у сводки или «✅ Пометить все как прочитанное» в журнале. Одиночное сообщение-уведомление помечается любой нажатой на нём кнопкой
- В списках событий (журнал и группы сводки) непрочитанные помечены **NEW** слева; список идёт **двумя столбиками**, а непарная последняя запись растягивается на всю ширину ряда — без пустых ячеек
- Под сводкой кнопки: **«Посмотреть все»**, **«✅ Прочитано»** (отметить все события сводки прочитанными), отдельные кнопки групп по уровням и «Главное меню»; из группы открывается список событий, из списка — карточка с кнопками действий и «Назад» обратно в группу. Переходы по сводке (группы, «Главное меню») закрывают её, не трогая статус непрочитанных — читать пойдёте в журнал
- В журнале событий под списком — длинная кнопка **«✅ Пометить все как прочитанное»** и строка «⬅️ Назад | 🗑 Очистить журнал»
- Задачи с live-выводом (скрипты, установка и удаление сервисов, полная проверка, операции Docker) **больше не дублируются уведомлением** от менеджера задач: результат уже показан в живом сообщении самой задачи, а событие остаётся в журнале для Web и истории
- Закрыта вечная пробка очереди: типы событий (general/ssh/update/script/key/service), не имевшие обработчика в кнопочном дрейне, копились в notification-очереди неделями — теперь дрейн забирает строки любого типа

#### ⚡ Отзывчивость

- Все блокирующие операции (SSH-подключения, проверки мониторинга, обновление сертификатов, генерация QR-кодов, импорт Compose-архивов) выполняются в фоновых потоках — бот и работающая с ним в одном процессе Web-панель не замирают на время сетевых операций
- Полная проверка сервисов: ожидание результата уходит в фон — кнопками бота можно пользоваться сразу, не дожидаясь обхода всех серверов
- Повторные авто-попытки SSH-подключения делают паузу в минуту после неудачи — панель больше не «забанивает» сама себя в fail2ban при недоступном сервере

#### 🔑 Ключи серверов

- Принять ключ переустановленного сервера можно прямо кнопкой в карточке сервера; события о несовпадении привязаны к конкретному серверу, баннер показывается в карточке, а кнопка принятия появляется только при реальном несовпадении

#### 🐛 Исправления интерфейса

- Оживлён сценарий добавления сервера по SSH-ключу: кнопки выбора ключа и ввода sudo-пароля вели на несуществующие маршруты
- Мастер установки сервиса больше не падает на сервисах без параметров
- Текстовые мастера (WireGuard, Docker, установка сервисов, SSL) закрываются любым переходом — кнопка «Назад» больше не оставляет ввод «висеть», и следующие сообщения пользователя не превращались молча в значения полей
- Экраны с пользовательскими именами (просмотр скрипта, очередь сервера) не падают из-за спецсимволов `_` и `*` в Markdown
- Битые декларации `BOT_PARAM` в скриптах сообщают об ошибке пользователю, а не молча роняют обработчик
- Ошибки списка образов Docker показывают свой экран с кнопкой повтора, а не обрываются
- Исправлен тост в карточке WireGuard после обновления элемента
- Удалён мёртвый код (недостижимая ветка SSL-мониторинга, неиспользуемые импорты)

## 5.0.0

# 🔐 Bot4VPS v5.0 — Безопасность, HTTPS и консольное меню

> **Панель умеет работать по HTTPS, секреты и резервные копии можно шифровать, вход защищается двухфакторной аутентификацией, а управлять установкой можно прямо с сервера через консольное меню.**

### 🔒 HTTPS для панели

- **Режимы**: off (как раньше), Let's Encrypt (certbot standalone, домен + e-mail), Self-signed (генерация на месте), Свой сертификат (внешние пути — без копирования — или загрузка файлов в Web), За прокси (доверенные IP/CIDR для X-Forwarded-Proto)
- Управление из Web (карточка «Сеть и доступ» в Настройках — порт и HTTPS в одном месте) и CLI (Безопасность → HTTPS сертификат); install.sh спрашивает про HTTPS при установке
- Перевыпуск кнопкой/пунктом меню; фоновое автопродление Let's Encrypt раз в сутки (обычный `certbot renew`, перезапуск панели только если сертификат реально обновился)
- Смена сертификата идёт в фоновом процессе с проверкой работоспособности и автоматическим откатом на HTTP при неудачном старте — панель не остаётся в нерабочем состоянии
- Кука сессии помечается Secure в HTTPS-режимах; схема определяется по systemd-юниту — единственному источнику правды
- Просрочка и дни действия сертификата видны в UI и CLI; предупреждение при рассинхроне «режим задан, панель работает без HTTPS»

### 🖥️ Консольное меню (CLI)

- Новая команда `bot4vps` на самом сервере (создаётся сервисом при старте; аналогично `python3 -m ui.cli`): статус, включение/выключение Web и смена порта, HTTPS-сертификат, настройка Telegram, перезапуск, обновление, журнал, удаление сервиса
- Раздел «Восстановление» — доверенный root-канал для починки панели, когда Web недоступен: диагностика, восстановление config.json из копии, восстановление Bot4VPS из архива, сброс конфигурации, перевыпуск кода первичной установки, аварийный сброс пароля Web и 2FA
- Управление мастер-ключом шифрования: состояние и «показать» (консоль — всегда доступный аварийный путь)

### 🔑 Шифрование секретов и мастер-ключ

- Пароли серверов, sudo и Telegram Bot Token шифруются на диске (значения с префиксом `enc1:` в `servers.json` / `config.json`); ключ — `keys/secret.key` (создаётся автоматически, права 0600)
- Карточка «Мастер-ключ» в Настройках → Безопасность: состояние ключа, кнопка «Зашифровать все секреты» (сканер всего ядра), восстановление при утере — ввести сохранённый ключ (данные сохранятся) или создать новый, тогда старые enc1: значения безвозвратно теряются и очищаются; просмотр значения строго после подтверждения — 2FA приоритетно, код в Telegram запасной, консоль — аварийный путь
- Инвариант ключа: если ключ не расшифровывает данные, панель не продолжает работу частично — запускается явный сценарий восстановления

### 💾 Backup: шифрование архивов и self-restore

- Опциональное шифрование архивов паролем (AES-256-GCM, формат B4VE) для копий установки Bot4VPS и серверных профилей; пароль требуется при просмотре, восстановлении и импорте
- «Забыл пароль» архива — сброс через подтверждение (2FA / код в Telegram / консоль)
- Self-restore: восстановление самой установки Bot4VPS из полного архива прямо из Web — операция идёт detached-раннером, переживает перезапуск панели (новый процесс подхватывает идущую операцию), с защитной копией и проверкой результата
- Копия установки корректно упаковывает каталог с локальным git-клоном (hardlinks больше не ломают архив)

### 🔥 Firewall: переключение бэкендов и стабильность

- Переключение UFW ↔ firewalld ↔ nftables с переносом правил: сводка правил обеих сторон, подтверждение переносимых портов, откат при неудаче
- Автоматическое создание базовой nftables-таблицы `bot4vps` и самовосстановление таблицы, если она устарела после переключения на другой бэкенд и перезагрузки
- Переключение на другой бэкенд больше не теряет правила прежнего — переносятся все правила, включая порт панели

### 🧭 Вход и первый запуск

- Новый экран входа — отдельная страница вне основного интерфейса: три темы, работает даже до завершения настройки
- Первый вход — по одноразовому коду первичной установки (выдаёт установщик, действует 10 минут, перевыпуск из CLI), затем мастер создаёт логин и пароль администратора
- Двухфакторная аутентификация Web (TOTP): QR-код из панели, recovery-код не обходит 2FA, аварийный сброс из консоли
- Двухфазное восстановление пароля: код в Telegram + собственный новый пароль
- Отключение защиты входа — подтверждённая операция: старый пароль + код 2FA (или код в Telegram, когда 2FA не включена); если второго фактора нет, подтверждением служит сам пароль. Смена пароля панели при выключенной защите тоже требует старый пароль — получив доступ к незащищённой панели, нельзя назначить свой пароль и включить защиту. Включение защиты сбрасывает текущую сессию — вход только заново, с паролем

### 🛡️ Защита от брутфорса

- Первый шаг входа ограничен: 10 неудачных попыток с одного адреса за 15 минут → 429 с Retry-After; успех сбрасывает счётчик

### 🐛 Исправления

- Установка: генерация кода первичной установки больше не гасит установку на чистой машине (SIGPIPE 141 под `set -o pipefail`); поиск certbot не загрязняет stdout; панель ждёт готовности после старта (до 15 с)
- Web: API создания сервера больше не возвращает пароль в ответе
- Firewall: классификация IPv6-цепочек ufw (`ufw6-*`) — переключение ufw→nftables больше не обрывается; при неудачной подготовке бэкенда возвращается понятная ошибка вместо `rollback_unverified`; деактивация прежнего бэкенда синхронизирует постоянные правила — bypass-правило не возвращается после перезагрузки
- Backup: web-driven self-restore не оставляет операцию «failed» при перезапуске панели в середине операции; проверка целостности не падает на изолированных записях каталога
- Backup: удалено неиспользуемое поле `automatic.timezone` — расписание всегда считается по локальному времени сервера, поле вводило в заблуждение в API (старые конфигурации вычищаются автоматически)

### 🛠️ Прочее

- Все ошибки HTTPS (занятый порт 80, DNS, лимиты Let's Encrypt, кривая пара сертификат/ключ) — с объяснением и подсказкой, что делать
- Health-check апдейтера, self-restore и смены порта понимают HTTPS-схему панели
- Фирменные иконки Docker и WireGuard в Web UI
