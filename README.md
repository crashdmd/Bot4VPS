## О проекте

**Bot4VPS** помогает следить за VPS и домашними серверами из одного места. Он подключается к ним по SSH, показывает текущее состояние, сообщает о проблемах и позволяет выполнять типовые административные действия без постоянного ручного входа на каждый сервер.

У Bot4VPS три интерфейса:

- **Web UI** — полноценная панель управления в браузере;
- **Telegram** — компактный интерфейс для телефона и уведомлений;
- **Консольное меню (CLI)** — управление прямо на сервере через SSH-сессию, включая аварийное восстановление, когда панель недоступна.

Все интерфейсы работают с одним списком серверов и общими данными. Можно использовать их вместе или установить только Telegram-бота.

Проект рассчитан на самостоятельное размещение: Bot4VPS устанавливается на ваш сервер, а сведения о подключениях и настройках остаются под вашим контролем.

## Возможности

Bot4VPS объединяет основные инструменты, которые нужны для повседневного наблюдения за несколькими серверами:

- просмотр доступности и состояния серверов;
- контроль SSH-подключения, нагрузки, памяти, диска и времени работы;
- проверка SSL-сертификатов;
- уведомления о недоступности сервера и его возвращении в сеть;
- быстрая проверка доступности из Web и Telegram;
- работа через браузер, Telegram и консоль на сервере;
- встроенный SSH-терминал в Web UI;
- HTTPS для панели: Let's Encrypt, свой сертификат, self-signed или работа за доверенным прокси;
- вход в панель с двухфакторной аутентификацией (TOTP);
- шифрование секретов на диске и мастер-ключ шифрования;
- Quick Setup: настройка SSH-доступа, менеджер SSH-ключей, firewall (с переключением UFW/firewalld/nftables и переносом правил) и установка пакетов;
- запуск собственных shell-скриптов;
- установка и обслуживание WireGuard и Docker;
- резервное копирование Bot4VPS и управляемых серверов с опциональным шифрованием архивов, включая восстановление самой установки из архива;
- журнал событий, мониторинг сервера с установленным Bot4VPS и обновление проекта.

## Управление серверами

Главная задача этого раздела — дать понятную картину состояния всех добавленных серверов. Для каждого сервера Bot4VPS может показывать:

- доступен ли сервер и работает ли подключение по SSH;
- имя системы, операционную систему и версию ядра;
- время работы после последней перезагрузки;
- текущую нагрузку, использование оперативной памяти и диска;
- состояние SSL-сертификата, если его проверка включена;
- недавние события и результат последней проверки.

Серверы можно объединять в группы, например по назначению или месту размещения. Это упрощает просмотр большого списка и позволяет отдельно управлять проверкой SSL для разных групп.

Bot4VPS регулярно проверяет серверы и отправляет уведомление, когда сервер становится недоступен или снова выходит в сеть. Доступность определяется сетевой пробой: ICMP-пинг, затем SSH-порт и порты 80/443 — так «закрытый» сервер без пинга и веба, но с работающим SSH, корректно считается доступным. Ошибка SSH-авторизации (например, сменённый пароль) не приравнивается к недоступности и показывается отдельным статусом. Системные данные (ОС, ядро, нагрузка) собираются фоновым SSH-опросом каждые 15 минут. Быстрая проверка доступности без SSH доступна по кнопке в Web и Telegram; при открытой панели статусы обновляются автоматически. Для SSL-сертификатов отслеживаются срок действия, истечение и обновление.

При добавлении сервера можно использовать пароль или SSH-ключ. Если для административных команд нужен отдельный пароль `sudo`, его можно указать отдельно. В интерфейсах также доступны необходимые действия с записью сервера и его перезагрузка, но основное назначение раздела — мониторинг и быстрый просмотр состояния.

## Web UI

Web UI — основной визуальный интерфейс Bot4VPS. Он открывается в обычном браузере и подходит как для компьютера, так и для мобильного устройства.

Через Web UI доступны:

- общий обзор состояния Bot4VPS и подключённых серверов;
- список серверов и подробные сведения о каждом из них;
- встроенный SSH-терминал для подключения к выбранному серверу;
- Quick Setup: настройка SSH-доступа (пользователи, порты, менеджер ключей), управление firewall и установка пакетов;
- WireGuard и Docker;
- пользовательские скрипты;
- работа с файлами проекта и конфигурациями Compose;
- резервные копии и восстановление, включая восстановление самой установки Bot4VPS из полного архива;
- мониторинг сервера, на котором работает сам Bot4VPS;
- журнал уведомлений;
- настройки Telegram, Web-доступа (порт, HTTPS, двухфакторная аутентификация, мастер-ключ шифрования), мониторинга, хранения истории и обновлений.

Длительные операции не блокируют панель. Они продолжаются в фоне, а их состояние и результат можно посмотреть в интерфейсе.

## Telegram

Telegram удобен для быстрого просмотра серверов и получения уведомлений в дороге. Доступ к боту разрешается только пользователям, чьи числовые идентификаторы добавлены в настройках Bot4VPS.

Через Telegram можно:

- просматривать группы, серверы и их состояние;
- получать уведомления о доступности и SSL-сертификатах;
- добавлять и изменять серверы;
- работать с SSH-ключами;
- запускать пользовательские скрипты и видеть результат;
- выполнять основные действия с WireGuard и Docker;
- запускать ограниченный сценарий резервного копирования и полного восстановления.

Telegram и Web UI используют общие данные, но не копируют друг друга полностью. Сложные формы, расширенная работа с файлами и полный набор возможностей Backup/Restore доступны в Web UI.

## Консольное меню (CLI)

На самом сервере доступна команда `bot4vps` (создаётся сервисом при старте; то же самое — `python3 -m ui.cli`). Она открывает текстовое меню в SSH-сессии и не требует работающей панели.

Через меню можно:

- посмотреть статус установки и сервиса;
- включать и выключать Web UI, менять порт и настраивать HTTPS-сертификат;
- настраивать Telegram;
- перезапускать сервис, обновлять Bot4VPS и смотреть журнал;
- управлять мастер-ключом шифрования (состояние и просмотр значения);
- удалить сервис.

Раздел «Восстановление» — доверенный root-канал для ситуаций, когда панель недоступна: диагностика, восстановление `config.json` из копии, восстановление Bot4VPS из архива, сброс конфигурации, перевыпуск кода первичной установки, аварийный сброс пароля Web и двухфакторной аутентификации.

## Резервное копирование и восстановление

Bot4VPS поддерживает два вида резервных копий:

- **копия самого Bot4VPS** — настройки, список серверов и другие данные установки;
- **копия управляемого сервера** — выбранные пользователем файлы и каталоги удалённого сервера.

В Web UI можно настроить источники и исключения, создать копию вручную или по расписанию, задать число сохраняемых архивов и просматривать историю операций. Каталог архивов позволяет проверить копию, посмотреть её содержимое, импортировать ранее созданный архив, скачать, переименовать или удалить его.

Восстановление может быть полным или выборочным. Перед изменением данных можно создать защитную копию текущего состояния. Это особенно важно, потому что после начала записи файлов отмена операции уже не всегда возможна.

Скопировать можно и саму установку Bot4VPS: восстановление полного архива запускается прямо из Web UI и выполняется в фоне, переживает перезапуск панели и возвращает установку к состоянию на момент создания копии — включая код, настройки и список серверов.

Архивы можно защищать паролем: при включённом шифровании содержимое шифруется по стандарту AES-256-GCM (формат B4VE), а пароль запрашивается при просмотре, восстановлении и импорте. Шифрование выключено по умолчанию и включается отдельно для копии установки и для каждого профиля сервера.

В Telegram доступен более короткий сценарий: создание копии управляемого сервера по заранее настроенному профилю и полное восстановление из доступного архива. Для этих действий Web UI должен быть включён и запущен. Настройка профилей, расписания и источников, импорт архивов и выборочное восстановление выполняются в Web UI.

По умолчанию полные архивы сохраняются локально в `/var/backups/bot4vps`. Они могут содержать настройки, SSH-ключи, пароли и пользовательские данные — как в открытом виде, так и в зашифрованном (при включённом шифровании архива). Доступ к этому каталогу необходимо строго ограничивать: если шифрование архива не включено, его содержимое читается любым, кто получил доступ к файлам.

## Quick Setup

Quick Setup — раздел Web UI для первичной настройки нового сервера. Он покрывает типовые действия, которые обычно выполняются вручную при подготовке VPS:

- **SSH-доступ** — создание пользователей, смена паролей, смена SSH-порта, управление входом root и аутентификацией по паролю;
- **SSH-ключи** — менеджер ключей per-user: создание, добавление готовых ключей, выбор ключа для входа Bot4VPS, безопасное отключение password-auth с переключением на ключ, реестр занятости ключей между серверами;
- **Firewall** — установка и управление UFW, firewalld или nftables, правила с протоколом ANY и Source IP/CIDR, переключение бэкенда с переносом существующих правил и подтверждением списка переносимых портов;
- **Пакеты** — каталог популярных утилит и сервисов с пакетной установкой;
- **Система и диагностика** — часы, hostname, swap, fail2ban.

Раздел учитывает фактические права: без sudo доступны только операции над собственным аккаунтом (свой пароль, свои ключи), а разделы, требующие суперпользователя, показывают соответствующее пояснение.

## Сервисы

Bot4VPS умеет устанавливать и обслуживать дополнительное программное обеспечение на подключённых серверах. Сейчас доступны WireGuard и Docker. Для таких операций серверу обычно требуется доступ через `sudo`.

### WireGuard

Раздел WireGuard помогает установить VPN-сервер, проверить его состояние и управлять профилями клиентов. Для клиента можно подготовить готовую конфигурацию или QR-код, чтобы быстрее добавить подключение на телефон или компьютер.

Также поддерживаются изменение основных параметров WireGuard, просмотр состояния клиентов и перенос существующей классической конфигурации под управление Bot4VPS.

### Docker

Раздел Docker позволяет установить Docker Engine и видеть его текущее состояние. Через Bot4VPS можно работать с контейнерами и образами, просматривать сведения и логи, а также управлять Compose-проектами.

Compose-проекты можно хранить в библиотеке Bot4VPS, развёртывать на выбранных серверах и импортировать с сервера обратно. Операции, способные изменить работающий сервис, требуют внимательной проверки параметров и подтверждения в интерфейсе.

## Скрипты и автоматизация

В Bot4VPS можно создать или загрузить собственный shell-скрипт, выбрать сервер и запустить его по SSH. Скрипт может запрашивать заранее описанные параметры: текст, число, переключатель или значение из списка. После запуска доступны состояние операции и её результат.

Скрипты подходят для повторяющихся действий, которые неудобно каждый раз выполнять вручную. Используйте только понятные и проверенные сценарии: такой скрипт получает те же права на удалённом сервере, что и настроенное SSH-подключение, а при использовании `sudo` может изменять всю систему.

Периодические проверки серверов, SSL-сертификатов и автоматические резервные копии выполняются по настроенному расписанию. Длительные действия запускаются в фоне, поэтому интерфейсы остаются доступными во время их выполнения.

## Установка

Установочный скрипт рассчитан на Debian или Ubuntu с `systemd`. Потребуются права `root`, доступ в Интернет и команда `curl`. Недостающие `git`, Python 3 и компонент `python3-venv` скрипт может установить через `apt`.

Запустите установку:

```bash
curl -fsSL https://raw.githubusercontent.com/crashdmd/Bot4VPS/main/install.sh | sudo bash -s -- install
```

Скрипт:

- установит проект в `/opt/bot4vps`;
- создаст отдельное Python-окружение и установит зависимости;
- предложит режим **только Telegram** или **Web + Telegram**;
- создаст и включит системный сервис `bot4vps.service`;
- при установке Web UI предложит порт, включит авторизацию, предложит настроить HTTPS (Let's Encrypt, свой сертификат или self-signed) и напечатает **код первичной установки** для создания учётной записи администратора;
- при активном UFW, firewalld или nftables добавит правило для выбранного Web-порта;
- создаст на сервере команду `bot4vps` для входа в консольное меню.

В режиме **только Telegram** установщик запросит токен бота и ваш числовой Telegram User ID. В режиме **Web + Telegram** первоначальную настройку Telegram можно завершить в Web UI.

После установки скрипт покажет состояние сервиса и, для Web UI, адрес вида `http://IP-сервера:порт/` (или `https://`, если настроен сертификат). Если адрес не открывается с другого устройства, проверьте внешний firewall или security group у VPS-провайдера. Для Let's Encrypt требуется домен, указывающий на сервер, и свободный порт 80.

Команды управления установленным проектом:

```bash
sudo bash /opt/bot4vps/install.sh status
sudo bash /opt/bot4vps/install.sh enable-web
sudo bash /opt/bot4vps/install.sh remove
```

- `status` показывает режим, состояние сервиса и наличие обновлений;
- `enable-web` добавляет Web UI к установке, которая раньше работала только через Telegram;
- `remove` предлагает удалить проект полностью или сохранить пользовательские данные для последующей установки.

## Настройка

При первом запуске нужно настроить интерфейсы и добавить хотя бы один сервер.

Для Telegram потребуются:

- токен, созданный через `@BotFather`;
- числовой User ID каждого пользователя, которому разрешён доступ.

В режиме только Telegram эти значения запрашивает установщик. В Web-режиме бот можно настроить и перезапустить на странице настроек.

Для входа в новый Web UI откройте панель и введите **код первичной установки**, который напечатал установщик (действует 10 минут; перевыпускается из консольного меню — «Восстановление → Код первичной установки»). Затем мастер предложит придумать логин и пароль администратора. Если код истёк или утерян, а панель уже настроена, пароль и двухфакторную аутентификацию можно аварийно сбросить из консольного меню на сервере.

При добавлении сервера указываются его адрес, SSH-порт, пользователь и способ входа — пароль или сохранённый SSH-ключ. Если выбранный пользователь не выполняет административные команды без пароля, дополнительно указывается пароль `sudo`.

В настройках Bot4VPS можно включать и выключать мониторинг, менять интервалы проверок, управлять Telegram, Web-доступом, уведомлениями, хранением истории и обновлениями.

Основные настройки хранятся в `/opt/bot4vps/config.json`. Не публикуйте этот файл и не вставляйте его содержимое в обращения или отчёты без удаления токенов, идентификаторов и других закрытых данных.

## Безопасность

Bot4VPS имеет доступ к вашим серверам, поэтому его следует защищать как административную панель.

- Добавляйте в `allowed_users` только доверенные Telegram-аккаунты. Один токен бота сам по себе не ограничивает доступ должным образом.
- При новой установке Web UI и при выполнении `enable-web` установщик включает встроенную авторизацию. Пароль хранится в виде хеша, а не открытым текстом.
- Отключение защиты входа и смена пароля при выключенной защите — подтверждённые операции: нужен старый пароль и, если настроен второй фактор, код из приложения-аутентификатора или Telegram.
- Включите двухфакторную аутентификацию (TOTP) в настройках панели: она подключается за минуту по QR-коду и не обходится recovery-кодом. Сбросить 2FA при утере устройства можно из консольного меню на сервере.
- Первый шаг входа защищён от брутфорса: после серии неудачных попыток с одного адреса панель отвечает временной блокировкой.
- По умолчанию Web UI доступен по обычному HTTP и слушает сетевые интерфейсы сервера. Не публикуйте его напрямую в Интернет без дополнительной защиты — включите встроенный HTTPS (Let's Encrypt, свой сертификат или self-signed) или разместите панель за доверенным reverse proxy.
- Для удалённого доступа также подойдут VPN и ограничение порта через firewall и security group.
- Храните SSH-ключи, пароли, Telegram-токен и `config.json` только на доверенном сервере с ограниченным доступом.
- Пароли серверов и Telegram Bot Token шифруются на диске (значения с префиксом `enc1:` в `servers.json` / `config.json`). Ключ шифрования — `/opt/bot4vps/keys/secret.key`, создаётся автоматически с правами `0600`. **Потеря этого файла делает зашифрованные секреты невосстановимыми**. Ключ сознательно не входит в архивы Backup/Restore (иначе шифрование внутри архива теряло бы смысл) — сохраните его отдельно от сервера: в менеджере паролей или надёжном хранилище. После восстановления Bot4VPS из архива панель попросит ввести сохранённый ключ.
- Мастер-ключ можно посмотреть в настройках панели (Настройки → Безопасность), но только после подтверждения — кодом 2FA, кодом в Telegram или из консоли. При утере ключа панель переходит в явный режим восстановления: можно ввести сохранённый ключ (зашифрованные данные сохранятся) или создать новый — тогда старые зашифрованные значения (пароли серверов, Telegram-токен, секрет 2FA) безвозвратно теряются и очищаются.
- Архивы Backup/Restore содержат секреты в том виде, в котором они хранятся у вас: включайте шифрование архива паролем (AES-256-GCM), если копии покидают доверенную инфраструктуру. Незашифрованные архивы читаются любым, кто получил доступ к файлам.
- Регулярно проверяйте права на `/opt/bot4vps` и `/var/backups/bot4vps`.
- Перед восстановлением или запуском незнакомого скрипта проверьте выбранный сервер, файлы и ожидаемый результат.

## Высокоуровневая архитектура

Bot4VPS можно представить простой схемой:

```text
Web UI ─────┐
             │
Telegram ────┼──> общее ядро Bot4VPS ──> SSH ──> управляемые серверы
             │                │
CLI ────────┘                └──> мониторинг, события и уведомления
```

Web UI, Telegram и CLI обращаются к общей логике и общим данным, поэтому изменения серверов и результаты операций доступны во всех интерфейсах. В режиме Web + Telegram они работают в составе одного системного сервиса; CLI — это отдельная команда на сервере для управления и аварийного восстановления.

Фоновые задачи мониторинга (сбор системных данных, проверка доступности, SSL, обновления) принадлежат ядру и запускаются вместе с самим Bot4VPS — независимо от того, включён ли Telegram и открыт ли Web UI. Интерфейсы лишь читают их результаты и получают события, поэтому выключение Telegram не останавливает мониторинг.

Отдельный внутренний слой выполняет длительные операции в фоне. Благодаря этому интерфейс не зависает во время установки сервиса, запуска скрипта, создания резервной копии или восстановления, а пользователь может следить за состоянием работы.

## Структура проекта

Ниже перечислены только основные файлы и каталоги, которые полезно знать пользователю или администратору установки:

```text
Bot4VPS/
├── bot.py          # запуск режима только Telegram
├── install.sh      # установка, обновление и управление сервисом
├── core/           # общая логика Bot4VPS
├── ui/             # Web UI, Telegram и консольное меню (CLI)
├── services/       # поддержка WireGuard и Docker
├── scripts/        # пользовательские shell-скрипты
├── keys/           # сохранённые SSH-ключи
├── data/           # рабочие данные и состояние функций
├── logs/           # история операций, событий и уведомлений
├── backup/         # служебные копии списка серверов
├── docs/           # дополнительные материалы проекта
├── requirements.txt
├── config.example.json
└── LICENSE
```

Каталог `/opt/bot4vps/backup/` содержит служебные копии данных о серверах и не заменяет полноценный Backup/Restore. Полные архивы Bot4VPS и управляемых серверов по умолчанию находятся в `/var/backups/bot4vps`.

## Обновление

Проверить и установить обновление можно в настройках Web UI. Перед установкой интерфейс показывает доступную версию и сведения об изменениях.

Обновление также запускается через установочный скрипт:

```bash
sudo bash /opt/bot4vps/install.sh update
```

Скрипт проверит ветку `main`, покажет доступные изменения, запросит подтверждение, обновит зависимости и перезапустит включённый сервис.

Если вы самостоятельно изменяли исходные файлы Bot4VPS, сохраните эти изменения отдельно до обновления. Установщик может временно убрать или заменить локальные изменения кода при синхронизации с основной веткой. Пользовательские настройки, серверы, ключи, скрипты и резервные копии также стоит включить в собственную регулярную схему резервного копирования.
