# Шлюзы OpenWrt

В Bot4VPS 7.5 шлюзы находятся в отдельном разделе перед серверами.
Кнопка «Добавить шлюз» находится в этом разделе. Если мастер сервера
обнаруживает OpenWrt, он предлагает перейти в мастер шлюза.
Управление включается в «Настройки → Параметры». На новой установке оно выключено;
существующие подключения сохраняют включённое управление. При выключении панель
предупреждает о прекращении опросов и закрывает свои RPC/SSH-подключения, включая
консоли. Записи и зашифрованные секреты сохраняются для повторного включения.
Во время применения сети или первоначального подключения нужно дождаться завершения
операции, чтобы не потерять её подтверждение.

## Подключение

Укажите адрес, SSH-порт, логин и пароль. Имя необязательно: пустое поле заполняется
моделью роутера, а при её отсутствии — hostname или адресом. Заданное вручную
имя используется вместо автоматического, в том числе при подключении готового API.
Проверка читает модель, версию OpenWrt и список пакетов, затем показывает план изменений.
Можно разрешить автоматическую настройку, отказаться или настроить API
самостоятельно. Ход настройки виден в журнале задачи.

Мастер устанавливает недостающие компоненты rpcd/uhttpd/LuCI, создаёт
отдельную RPC-учётную запись и ключ подписи операций, проверяет HTTPS.
SSH-доступ сохраняется для консоли. Пароли SSH/API и приватный ключ
подписи шифруются мастер-ключом панели; API не возвращает их в браузер.

В LuCI доступом управляет раздел **«Службы → Bot4VPS»**. Он позволяет
отключить доступ и перевыпустить секрет. После перевыпуска укажите новый
секрет во вкладке «Доступ» шлюза. SSH-данные при этом сохраняются.
Компонент LuCI входит в панель; мастер устанавливает его файлы на роутере.

Для вручную настроенного API укажите HTTPS `/ubus`, отдельную учётную
запись и, для собственного сертификата, SHA-256 его сертификата.
Доступные функции определяются правами и установленными компонентами.
Примеры адресов: `192.168.1.1` для SSH и `https://192.168.1.1/ubus` для API.

## Мониторинг и управление

Карточка показывает CPU, память, место, температуру при наличии датчика,
интерфейсы и скорости трафика, DHCP-аренды, Wi-Fi и WireGuard при наличии
соответствующих данных. Отсутствующий компонент не изображается остановленным
сервисом. При потере API сохраняется последний снимок и его время проверки.

Для предусмотренных операций используются подписанный план, очередь задач,
живой журнал и проверка результата новым HTTPS-подключением. Запуск, остановка
и перезапуск проверяются с восстановлением прежнего состояния службы,
если панель не подтверждает результат. Изменившийся после просмотра состав
пакетов требует нового плана.

Во вкладке **«Сеть»** доступны подключение, отключение и переподключение,
формы LAN/WAN, статического адреса, DHCP-клиента, PPPoE, WireGuard и маршрутов
IPv4. Перед применением показывается план. UCI-конфигурация подготавливается
отдельно; сеть изменяется только после подтверждения. Если панель не проверит
конфигурацию и доступность за 120 секунд, роутер самостоятельно восстановит
предыдущее состояние. При смене LAN-адреса проверяется именно новый HTTPS-адрес,
после чего панель сохраняет его для API и SSH. Форма отказывается перезаписывать
сеть, изменённую в LuCI после её открытия. Пароли PPPoE и ключи WireGuard
не возвращаются в браузер; пустые поля сохраняют существующие секреты.

Во вкладке **«Пакеты»** есть обновление списка репозиториев, поиск доступных
и установленных пакетов, просмотр рассчитанного плана установки и живой журнал.
Установка из штатных репозиториев роутера отличается от резервных комплектов
Podkop/SSClash: она использует сетевой доступ роутера и штатные установочные
скрипты пакетов. План, требующий замены, удаления или обновления уже установленных
пакетов, отклоняется. Обновление списка само по себе не обновляет установленные
пакеты. Во вкладке «Сеть» доступны явные настройки DNS dnsmasq и DHCP для каждого
подключения. DHCP меняет диапазон, срок аренды и DNS (option 6), сохраняя другие
опции и IPv6. Диапазон проверяется по подсети и адресу самого роутера.
Карточка firewall открывает общие настройки, зоны, правила трафика и
перенаправления портов; перезапуск и изменения проходят через снимок UCI,
подписанный план и автономный откат. Расширенные настройки и IPv6-маршруты
доступны в LuCI.
Прошивка и установленные пакеты автоматически не обновляются.

## Перенаправление портов

В **«Службы → Firewall → Настроить»** откройте вкладку
**«Перенаправление портов»**. В Mobile она находится в настройках Firewall
на странице **«Сервисы»** шлюза. Можно создать, изменить или удалить обычное
перенаправление DNAT; специальные правила NAT в этой форме не изменяются.

Укажите исходную зону, протокол TCP/UDP, внешний порт, зону и IP устройства
назначения. Внутренний порт можно оставить пустым, чтобы сохранить внешний.
Поддерживаются диапазоны портов. Например, TCP `8443` из `wan` можно направить
на `192.168.1.10:443` в зоне `lan`. Существующие пользовательские зоны вроде
`guest-wifi` доступны наравне с `lan` и `wan`.

Поле адреса источника ограничивает доступ одним IP или подсетью CIDR.
Пустое поле означает любой адрес; подсеть `/0` также не ограничивает источник.
План для WAN прямо сообщает: **«Порт будет доступен из интернета»** и показывает,
есть ли ограничение по адресу источника. Проверьте защиту сервиса назначения
и доступность WAN у провайдера до подтверждения.

Кнопка **«Проверить изменения»** сначала готовит план. Правило применяется
после подтверждения с перезапуском firewall и проверкой связи; неподтверждённая
конфигурация откатывается, если панель не подтвердит результат за 120 секунд. Если вкладка недоступна или панель
сообщает о несовместимом API, обновите интеграцию во вкладке **«Доступ»**.

**«Консоль шлюза»** открывает SSH-терминал с сохранёнными данными.
Поддерживаются обычный ввод, Ctrl+C и изменение размеров. Команды выполняются
напрямую: автоматический откат для произвольных консольных команд не применяется.
Аудит фиксирует пользователя, устройство, открытие и закрытие сеанса;
содержимое терминала и введённые команды в журнал не записываются.
Сеанс закрывается при удалении шлюза, смене SSH-данных или отзыве авторизации.

## Установка и удаление сервисов

Каталог во вкладке «Службы» («Сервисы» в Mobile) содержит [Podkop](https://github.com/itdoginfo/podkop),
[SSClash-Go](https://github.com/zerolabnet/SSClash-Go) и
[AdGuard Home](https://github.com/AdguardTeam/AdGuardHome).
В Web UI кнопка «Открыть SSClash» в карточке установленной службы открывает адрес
шлюза и порт её веб-интерфейса в новой вкладке (по умолчанию `9091`).
В Mobile веб-интерфейсы сервисов открываются во встроенном браузере.
Выбранный релиз и зависимости сначала сохраняются на панели для конкретных
версии OpenWrt, архитектуры и ABI ядра. Затем отдельное подтверждение запускает
установку из полного комплекта с отключёнными внешними источниками и пакетными
скриптами. Установленные совместимые зависимости не заменяются.
Запуск сервиса выполняется отдельно от установки.

По желанию можно хранить резерв последних двух или трёх совместимых версий.
Резервирование скачивает файлы только на панель. Отключение автоматического
резервирования сохраняет уже зарезервированные версии; временные комплекты
для разовой установки очищаются. Активный установочный план защищает свой
комплект от очистки.

Удаление показывает принадлежащие сервису файлы и сохраняемые зависимости.
При выбранном резерве путь к архиву конфигурации появляется в журнале.
Пакеты, настройки и каталоги сервиса удаляются; общие зависимости сохраняются.
Переустановка поверх существующего сервиса требует сначала удалить его
с резервом конфигурации.

## Встроенный браузер Mobile

В Bot4VPS Mobile кнопки открытия Podkop, SSClash-Go, AdGuard Home и LuCI
открывают интерфейс внутри приложения. Телефону нужен доступ только к HTTPS
Mobile API панели. VPN на телефоне и открытие веб-порта сервиса из WAN для
этого не требуются; панель должна видеть сервис напрямую или через сохранённый SSH.

Вход выполняется обычным логином и паролем выбранного сервиса. Кнопка
**«Закрыть»** в верхней панели завершает окно независимо от истории страниц.
При закрытии очищаются данные браузера этого сервиса. Внешние ссылки,
выбранные пользователем, открываются обычным браузером телефона.

При временном обрыве есть до 60 секунд на восстановление ответа сервиса.
Если связь не восстановилась, доступ завершается с сообщением. Команды
автоматически не повторяются. Меню и нижние уведомления SSClash-Go учитывают
видимую область окна, поворот телефона и появление клавиатуры.

## AdGuard Home

Панель выбирает официальный GitHub-бинарный архив по архитектуре роутера и
проверяет его по `checksums.txt` релиза. На роутер передаётся только проверенный
исполняемый файл; установщик GitHub не запускается. Служба procd устанавливается
в `/opt/AdGuardHome`, с выключенным автозапуском и без изменения DNS/DHCP/firewall.
Комплект может храниться на панели и устанавливается без доступа роутера к GitHub.

Во вкладке «Пакеты» кнопка «AdGuard Home: настройка DNS» показывает занятые
порты, свободное место и последовательность настройки. Первый запуск открывает
мастер на адресе управления, TCP 3000. Веб-порты 80/443 обычно заняты LuCI.
Для первого теста оставьте dnsmasq на 53, AdGuard Home настройте на 5353,
с собственными upstream/bootstrap DNS и с выключенным DHCP. Проверьте запросы
и журнал до изменения DNS роутера. Обычные upstream AdGuard Home нельзя
направлять обратно в dnsmasq, если dnsmasq пересылает запросы в AdGuard Home.

После проверки можно изменить upstream dnsmasq на адрес роутера и порт 5353
через подписанный план DNS. DHCP и nftset/ipset-настройки сохраняются.
Полная замена DNS на порту 53 требует переноса dnsmasq на 54 и проверки
локальных/PTR resolver и правил обхода. Следуйте
[официальной инструкции OpenWrt](https://openwrt.org/docs/guide-user/services/dns/adguard-home)
и [Getting Started](https://github.com/AdguardTeam/AdGuardHome/wiki/Getting-Started).
API-проверка и откат защищают доступ к панели; работу DNS нужно также проверить
с клиентского устройства. Скрипт удаления из сторонних инструкций не выполняется.

Перед остановкой или удалением панель проверяет DNS-зависимости. Если dnsmasq
ссылается на AdGuard Home или оставлен без DNS на 53 при работе AdGuard Home на 53,
сначала верните рабочую схему DNS. Удаление убирает принадлежащие установке
каталог, службу и автозапуск; конфигурацию можно сохранить в резерв. Установку
другого происхождения удаляют её исходным пакетным менеджером/установщиком.

Первоначальное подключение ведёт журнал установки на роутере. При ошибке
созданный доступ отзывается, собственные файлы и изменения HTTPS восстанавливаются
по контрольным суммам. Параллельные изменения и используемые другими пакетами
зависимости не перезаписываются; незавершённый откат явно отражается в журнале.
Перед операцией сверяются версия контракта и контрольные суммы RPC-компонентов.

## Удаление шлюза

Удаление начинается с плана. Для созданной панелью интеграции до отзыва API
проверяются сохранённый SSH-доступ, ключ хоста, другие подключения Bot4VPS
и контрольные суммы принадлежащих интеграции файлов. Неизвестные изменения
файлов блокируют отзыв до решения проблемы; они автоматически не удаляются.

Панель отзывает только собственную API-учётную запись, её сеансы, ACL и ключ
подписи, затем проверяет очистку. При сохранённом root SSH отзыв выполняется
через SSH и не требует работающего API. В остальных случаях используется API
с возможностью проверить отзыв через сохранённый SSH. Выбранный путь виден в плане.

Файлы интеграции и пункт «Службы → Bot4VPS» удаляются после отзыва. При наличии
других подключений общие компоненты сохраняются до удаления последнего.
Если отзыв или очистку не удалось подтвердить, запись шлюза остаётся для повторной
попытки. LuCI, rpcd, uhttpd, SSH, сеть и установленные сервисы сохраняются.

SSH-вход пользователя, LuCI, сеть и установленные сервисы роутера сохраняются.
Повторное добавление через SSH создаёт новый API-секрет.

## Интеграция и восстановление API-доступа

Во вкладке **«Доступ»** управляемого шлюза с сохранённым SSH нажмите
**«Обновить интеграцию Bot4VPS»**, просмотрите план и подтвердите его.
Панель проверяет принадлежность API-учётной записи и контрольные суммы файлов,
сохраняет прежние компоненты и устанавливает версии из текущей панели.
Учётные записи, секреты, установленные сервисы и сеть сохраняются. Изменённые
вне известной установки файлы обычное обновление не перезаписывает.
После замены проверяется API; при ошибке компоненты возвращаются из резервной копии.

Если собственная API-учётная запись уже отозвана, эта же проверка предложит
**восстановление через root SSH**. В Mobile при незавершённом удалении кнопка
называется **«Восстановить отозванный API через root SSH»**. Нужны сохранённый
и проверенный root SSH-доступ и отсутствие других подключений Bot4VPS на роутере.
Если учётная запись ещё существует, для смены секрета используется раздел
доступа LuCI; восстановление отозванной записи не запускается.

План восстановления перечисляет заменяемые файлы. После подтверждения они
сохраняются в резервную копию; восстановление может заменить старые или вручную
изменённые обычные файлы из этого списка. Создаются новый API-секрет и новый
ключ подписи. Прежний секрет не возобновляется. Панель проверяет API до сохранения
нового доступа, сохраняя существующую запись шлюза, SSH, LAN/WAN, Wi-Fi и сервисы.
При ошибке до сохранения созданный доступ отзывается, а файлы возвращаются по журналу.

Если очередь отказала в постановке задачи, подтверждённый план остаётся доступен
для повторной попытки до истечения срока. Успешно поставленная задача второй раз
по тому же плану не запускается. При неизвестном результате уже начатой операции
сначала проверьте её журнал и состояние шлюза.

## Проверенная совместимость

| Ветка | Проверенный стенд | Пакеты |
| --- | --- | --- |
| 23.05 | 23.05.6, x86/64 | opkg; совместимые релизы Podkop до 0.5 |
| 24.10 | 24.10.5, x86/64 | opkg; Podkop и SSClash |
| 25.12 | 25.12.6, x86/64 | APK 3; Podkop и SSClash |

Подключение и системный мониторинг проверены на всех трёх стендах.
Полные комплекты, установка и удаление Podkop/SSClash проверены на 24.10/25.12.
На физическом оборудовании датчики, Wi-Fi и доступные RPC-компоненты могут
различаться; панель показывает найденные возможности.

Подготовка APK на панели использует переносимый apk-tools 3 с закреплённой
SHA-256 из официального Alpine-источника. Подписанные индексы проверяются
публичными ключами OpenWrt. Обработчик распаковывается в кэш панели и не
устанавливает пакеты в операционную систему панели.
Адреса каталогов и файлов индексов APK приводятся к одному формату; официальные
HTTP-источники запрашиваются через HTTPS. В журнале перечисляются проверенные
индексы и количество пакетов подходящей архитектуры. Отсутствующие источники
отличаются от отсутствующей зависимости. Ошибка отдельной версии комплекта
не отменяет проверку остальных выбранных версий и сервисов.
Имя CPU, возвращаемое `apk --print-arch`, может отличаться от архитектуры
официальных пакетов: например, `aarch64` и `aarch64_cortex-a53`. Панель сверяет
архитектуру пакетов с `arch_packages` в официальном `profiles.json` точной
версии и платформы OpenWrt. Она используется при чтении индексов, проверке
файлов и загрузке зависимостей; исходная идентичность шлюза сохраняется.

Автоматическое обновление пакетов и обязательное обновление прошивки отсутствуют.

## Резервные копии настроек шлюзов

В карточке шлюза есть отдельная вкладка «Резервные копии». Создание вызывает
штатный `sysupgrade -b`, как в LuCI, и сохраняет проверенный архив на панели.
Прошивка и установленные пакеты в него не входят. Состав файлов определяется
штатным списком OpenWrt, включая пользовательские настройки sysupgrade.

Каталог копий общий: любой архив можно выбрать для любого шлюза. Модель,
версия OpenWrt и имя источника служат справочной информацией и не ограничивают
восстановление. Свой архив tar.gz можно загрузить через меню восстановления.
В «Файлы → Копии шлюзов» доступны скачивание и удаление; вкладка отображается
только при наличии копий. Шлюзы исключены из списка целей обычного меню Backup.

Перед восстановлением проверяются gzip/tar, размер, контрольная сумма,
типы файлов, ссылки и пути. Проверенный план привязан к выбранному шлюзу и
браузеру/устройству, а архив остаётся общим. До подтверждения файлы настроек
не меняются. После подтверждения на панели сохраняется защитная штатная копия
текущих настроек, затем `sysupgrade -r` записывает выбранный архив.
Перезагрузка подтверждается отдельно; её состояние сохраняется после
перезапуска панели. Если восстановлены другие настройки API, перезагрузку
можно выполнить через LuCI. Адрес, интерфейсы, Wi-Fi и доступ после запуска
определяются содержимым архива. Автоматический откат восстановления не обещается.

Активные планы защищают выбранные архивы от удаления. Частично загруженные
копии не публикуются, а скачивание архивов не кэшируется браузером. Для новых
действий на ранее подключённом шлюзе требуется явная синхронизация интеграции
во вкладке «Доступ». Архивы могут содержать пароли и ключи доступа.

## Wi-Fi и DHCP-клиенты

На вкладке «Сеть» DHCP-клиенты доступны с поиском по имени, IP и MAC и страницами
по 20 записей. Подключения и маршруты остаются на этой вкладке.

На отдельной вкладке «Wi-Fi» можно изменить SSID, пароль, защиту, канал и ширину
канала, страну и мощность, привязку к сетевым подключениям, скрытие SSID,
изоляцию клиентов и включение радиомодуля или отдельной сети. Пустое поле
пароля сохраняет текущий пароль. Неизменённые параметры UCI сохраняются.
Перед применением показывается план; если панель не подтвердит конфигурацию
и доступность API, роутер восстановит предыдущий Wi-Fi в течение 120 секунд.

Кнопка «Просмотр каналов» запускает сканирование через стандартный RPC iwinfo
(`rpcd-mod-iwinfo`) напрямую из панели. Чтение настроек и открытие вкладки
не запускают сканирование. Обработчик Bot4VPS внутри rpcd не вызывает iwinfo,
обслуживаемый тем же процессом. Старый несовместимый Wi-Fi API отклоняется
до чтения настроек; для него требуется обновить компонент на роутере.
В результатах показаны каналы, частоты, соседние сети,
уровень сигнала и защита. При наличии утилиты `iw` и поддержки survey драйвером
показываются шум и занятость эфира за интервал измерения. Если драйвер не
возвращает счётчики, вместо процента отображается «—». Количество сетей
не подменяет занятость эфира и учитывает основной канал каждой сети;
широкие каналы могут перекрываться. Сканирование может ненадолго замедлить Wi-Fi.

Каталог GitHub, выбор версий и резервные комплекты находятся в «Службах».
Настройка DNS AdGuard Home открывается из его строки в каталоге.
Firewall представлен строкой с описанием и кнопкой настроек; общие настройки,
зоны, правила трафика и перенаправления портов разделены вкладками. Удаление шлюза находится справа вверху
вкладки «Доступ» и по-прежнему требует просмотра плана отзыва API.

На главном обзоре виджет показывает один шлюз и переключается между ними
каждые пять секунд. Внутри шлюза показатели и графики трафика размещены компактно.
Периоды графиков: час, 6 часов, 12 часов и сутки. История накапливается до суток
в памяти панели; перезапуск начинает её заново. Для выбранного периода выдаётся
не более 240 точек с усреднением скоростей, без дополнительных опросов роутера.
Обзор Wi-Fi каналов показывает сигнал и перекрытие соседних сетей, а также
измеренную драйвером занятость. Открытие графика не включает повторное сканирование.

Во «Файлы → Сервисы» отображаются только сохранённые на панели установочные
копии 3x-ui, SSClash-Go, AdGuard Home и Podkop. У каждой указаны назначение
(VPS/Linux или OpenWrt), версия системы и архитектура. Можно посмотреть файлы,
скачать их и удалить локальную копию. Используемые установкой или планом файлы
защищены от удаления; общие зависимости других комплектов сохраняются.
Вкладка скрыта, если установочных копий нет. Удаление копии не удаляет сервис
с VPS или шлюза. При включённом резервировании удалённая версия может скачаться снова.

Группы установочных копий объединены по сервисам и изначально свёрнуты.
Раскрытые группы сохраняют состояние при обновлении списка; внешний контейнер
не имеет рамки. Окно установки служб в карточке шлюза показывает компактные
раскрываемые строки с выбором версии и действиями внутри.

Успешный опрос API шлюза сохраняет нагрузку, память и корневое хранилище
в общей БД метрик для раздела мониторинга, без дополнительного подключения.
История этих метрик сохраняется при перезапуске панели.


### Проверка комплектов и обновление сервисов

При включённом резервировании новое подключение сразу ставит проверку своей
платформы в очередь. Ручная кнопка «Загрузить комплекты сервисов» во вкладке
«Файлы → Сервисы» ставит отдельную задачу для каждого добавленного шлюза.
Ошибки постановки в очередь или загрузки одного шлюза не прерывают остальные;
общий результат сохраняет предупреждение об ошибках.
Она загружает файлы на панель и не устанавливает сервисы на роутерах. Для
каждой платформы сохраняется заданное количество последних совместимых версий;
подтверждённые планы и файлы отката защищены временными pin-записями.
Для APK выбираются релизы, содержащие APK, а для SSClash учитывается наличие
бинарного файла нужной архитектуры. Если старый API не возвращает источники,
панель читает официальные `profiles.json` выбранной версии и платформы,
подбирает каталоги пакетов и kmods по точному ABI ядра. Роутер при этом не меняется.

Сохранённые копии внутри сервиса разделены вкладками OpenWrt 24, 25 и других
веток. Удаляются отдельная копия или вся ветка сервиса; занятая установкой
или планом группа не удаляется частично. Общие объекты других комплектов
сохраняются. Пустые сервисы и пустые ветки не отображаются.

В карточке шлюза список сервисов проверяет совместимые обновления. Версия
бинарной службы определяется по сохранённой записи и контрольной сумме либо
по совпадению с локальным комплектом; неизвестная версия не выдаётся за старую.
Если версию установленного SSClash-Go или AdGuard Home определить не удалось,
кнопка «Указать установленную версию» позволяет явно подтвердить её. Запись
связана с SHA-256 текущего бинарного файла; при замене файла она перестаёт
подтверждать версию новой установки.
Управляемый AdGuard Home, SSClash-Go и Podkop обновляются через подготовку
комплектов, просмотр подписанного плана и подтверждение результата. Настройки
и состояние службы сохраняются. Для Podkop требуется исходный пакетный
комплект, точно совпадающий с установленной версией; без него обновление
останавливается до изменения роутера. Ошибка исполнения запускает возврат
исходных файлов/пакетов, а неподтверждённые параллельные изменения не затираются.
Подготовка сохраняет план на панели до завершения фоновой задачи. Для одного
сервиса повторные запросы используют существующую задачу либо предлагают
подтвердить уже подготовленный план. План привязан к задаче и окну/устройству
пользователя; поздний ответ другой задачи не подменяет его. Для APK откат
фиксирует точные версии пакетов и подготовленных зависимостей; сначала
выполняется проверка зависимостей без применения изменений.

### Результат подключения и контракт

После сохранения записи шлюз считается подключённым. Неудачный первый сбор
метрик не превращает подключение в ошибку. Не подтверждённая фиксация SSH-
транзакции сохраняется как `commit_pending`: повторить только фиксацию можно
во вкладке «Доступ», без создания новой учётной записи. Во время подключения,
фиксации, управления службами/сетью и удаления шлюза выключение OpenWrt-модуля
запрещено. Все SSH-подключения мастера регистрируются через общий транспорт.
Контракт проверяет весь перечень установленных компонентов, включая ACL,
отзыв доступа, LuCI и шаблоны init-скриптов. Старые компоненты требуют
синхронизации до выполнения подписанных изменений.
Порядок обновления компонентов и восстановления отозванной записи описан
в разделе [«Интеграция и восстановление API-доступа»](#интеграция-и-восстановление-api-доступа).

Черновик подключения хранится в общем каталоге панели, SSH-пароль зашифрован
мастер-ключом. Ожидание подтверждения ограничено пятью минутами. До подтверждения
черновик можно прочитать после перезапуска процесса; запуск фиксируется под
общей блокировкой. Прерванная подтверждённая операция автоматически не повторяется.

### Firewall, доступ служб и HTTPS

Изменения firewall, включая разрешение доступа из WAN, проходят через план
и явное подтверждение. План объясняет последствия политик зон, разрешающих
правил и удаления блокирующих правил; WAN не запрещён отдельным ограничением.
Новая установка SSClash слушает LAN. Отдельная подтверждаемая операция меняет
прослушивание LAN/WAN; для подключения извне также нужны соответствующие
правила firewall. План указывает на отсутствие HTTPS, если TLS веб-панели
не настроен. Существующие нестандартные init-скрипты автоматически не заменяются.
Изменение сохранённого TLS-отпечатка API требует отдельного подтверждения;
поле отпечатка при первоначальном подключении остаётся необязательным.

### Wi-Fi и интерфейс

Контуры соседних сетей и занятость эфира представлены на одном графике с
двумя подписанными шкалами и легендой. Отсутствующая в iwinfo частота
восстанавливается по каналу выбранного радиомодуля. Наведение меняет строку
подсказки фиксированной высоты, сохраняя размеры окна. Страна и мощность
выбираются из списков драйвера; API проверяет их повторно. Режимы HT/VHT/HE/EHT
подписаны поколением Wi-Fi и шириной полосы. История трафика обновляется каждые
30 секунд, а текущие показатели — отдельно. Диалоги учитывают `summary` при
перемещении фокуса клавишей Tab.
Текущие показатели запрашиваются через `/api/gateways/status` без истории
графиков; полный список загружается при открытии, возврате фокуса и действиях
пользователя. В скрытой вкладке браузера опросы интерфейса не выполняются.

## Передача локальных комплектов

Установочные архивы остаются на панели. При выполнении подписанной операции
панель сначала проверяет сохранённый root SSH-доступ и закреплённый ключ шлюза.
Если вход подтверждён командой `id -u`, файлы передаются бинарным потоком SSH;
SFTP и bash на OpenWrt не требуются. При недоступности SSH используется HTTPS
API. Отказ получателя из-за подписи, лимита или контрольной суммы завершает
операцию с ошибкой и не вызывает переход на другой транспорт.

SSH-получатель проверяет существующий план, nonce, пользователя, срок действия,
фазу `prepared`, подпись manifest и разрешённые имена, размеры и SHA-256.
Он записывает временный файл и публикует его только после проверки хеша,
пока план ещё ожидает данные. Общий лимит временных файлов — 128 МиБ.
Штатный worker повторно проверяет подпись и хеши перед выполнением;
подтверждение результата и восстановление сохраняются. Журнал показывает
канал передачи, объём и скорость.
