# Встроенный браузер Mobile

Кнопка открытия 3x-ui, Podkop, SSClash-Go или AdGuard Home открывает сервис внутри приложения. Телефон подключается только к HTTPS Mobile API панели; включать VPN телефона или разрешать веб-порт сервиса в WAN не требуется. Пользователь входит в самом сервисе его обычным логином и паролем.

Панель выбирает адрес и порт из настроек зарегистрированного узла и фактических сведений сервиса. Для узла с проверенным SSH-доступом используется SSH direct-tcpip к loopback или к IP, назначенному собственному интерфейсу роутера. При отсутствии SSH на шлюзе панель должна напрямую видеть веб-интерфейс. HTTPS при прямом доступе проверяется по системному доверию или сохранённому сертификату LuCI.

Страницы имеют отдельный локальный origin в WebView телефона. Данные HTTP и WebSocket передаются через WSS API панели. Страницы сервиса не получают сессию устройства и не выполняются на origin панели. Cookies сервиса очищаются при закрытии окна. Изменение адреса панели, отзыв устройства, истечение сессии и удаление либо изменение доступа к узлу прекращают канал.

В верхней панели есть отдельная кнопка «Закрыть»: она завершает сервис независимо от истории страниц. Ресурсы кешируются в пределах открытого окна с учётом HTTP-заголовков сервиса; соединения повторно используются, а HTTP gzip декодируется после передачи через WSS.

Для ответа сервиса с `Referrer-Policy: no-referrer` локальный прокси использует `same-origin`. Chromium иначе отправляет обычную форму входа с `Origin: null`, которую проверка локального origin отклоняет. Новый режим передаёт Referer только внутри изолированного сервиса. Проверка origin и локального HttpOnly cookie сохраняется; сессия панели странице не передаётся.

Внутренние маршруты:
- `POST /api/service-browser/{node_id}/{service}/open` — подготовка сессии для конкретного сервиса;
- `DELETE /api/service-browser/{session_id}` — закрытие;
- `WSS /api/service-browser/{session_id}/stream` — поток байтов к фиксированному сервису.
- `WSS /api/service-browser/{session_id}/control` — контроль окна и доступности выбранного сервиса.

Эти маршруты принимают только проверенную привязку HTTPS Mobile API. Внешние ссылки, открытые пользователем, переходят в обычный браузер. Архивы установки сервисов остаются на панели.

Открытие требует протокол 2 (`{"protocol":2}`). Сессия принадлежит конкретному проверенному телефону, данные разрешены только с подключённым контрольным каналом. Панель проверяет Host каждого HTTP-запроса, запрещает абсолютные URL, CONNECT и заголовки переадресации. WebSocket разрешается после настоящего подтверждения handshake выбранным сервисом.

Контрольный канал проверяет ответ выбранного сервиса и допускает восстановление связи в течение 60 секунд. Отсчёт идёт от последнего ответа шлюза, а не от heartbeat телефона. Если ответа нет, сессия удаляется и её соединения закрываются. Краткий разрыв контрольного канала позволяет владельцу переподключиться в пределах минуты. Закрытие окна, отзыв телефона и успешный выход внутри сервиса завершают туннель; cookies и локальное хранилище WebView очищаются. При обрыве команды не повторяются автоматически.
