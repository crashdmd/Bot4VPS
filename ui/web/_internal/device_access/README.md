# Подключение мобильного приложения

Режим обкатки отдельного API. По умолчанию раздел настроек скрыт, маршруты управления привязками не зарегистрированы и API-порт закрыт. Режим включается явно в окружении службы Bot4VPS.

Приложение подключается к серверу Bot4VPS через отдельный HTTPS-порт. Локальная веб-панель используется для настройки доступа и привязки телефона; она может работать по HTTP в доверенной сети. API использует собственный ключ и сертификат. Оба интерфейса работают с одним мониторингом, Telegram и очередью задач.

## Включение

Добавьте в окружение службы:

```ini
[Service]
Environment=BOT4VPS_MOBILE_API_PREVIEW=1
```

Для systemd можно использовать `sudo systemctl edit bot4vps.service`, затем выполнить:

```bash
sudo systemctl daemon-reload
sudo systemctl restart bot4vps.service
```

Откройте веб-панель по локальному IP, например `http://192.168.1.5:8080`. В настройках сразу под «Безопасностью» появится «Мобильное приложение». При включённой авторизации сначала требуется обычный вход.

Если панель открывается по DNS-имени, укажите её точный адрес в окружении службы:

```ini
Environment=BOT4VPS_MOBILE_API_WEB_ORIGIN=http://panel.example.com
```

Адрес должен совпадать со схемой, именем и портом в браузере. По умолчанию управление привязками доступно через локальный IP/localhost; явное разрешение DNS-имени защищает от DNS rebinding. При использовании обратного прокси ограничьте доступ к этому веб-адресу доверенной сетью: сервер видит адрес прокси, а не посетителя. Заголовок `X-Forwarded-For` не используется для разрешения доступа.

В разделе задайте:

- **Адрес для приложения** — доступный телефону HTTPS-адрес API с портом, например `https://api.example.com:8444`. Поддерживается IP; домен необязателен. Если порт не указан, используется 443.
- **Порт API на сервере** — например `8444`, отличный от порта веб-панели.
- **Разрешить подключение приложения** — включите и сохраните.

Настройки применяются сразу. Статус обновляется каждые три секунды; работающий API выделяется зелёным. Ошибки показаны в форме, введённые поля сохраняются во время опроса. Опрос останавливается при уходе из раздела и приостанавливается в скрытой вкладке.

## Сетевой доступ

При включении открывается TCP-порт API в локальном файрволле сервера Bot4VPS, при выключении правило удаляется. Смена порта переносит правило; при ошибке выполняется восстановление прежнего состояния. Настройки добавленных серверов не затрагиваются.

Поддерживаются активный UFW, firewalld и управляемая входящая цепочка собственной таблицы `inet bot4vps`. Учитываются только правила API, существующие правила других сервисов сохраняются. Для вручную настроенного iptables или сторонних цепочек nftables панель сообщает о невозможности автоматического применения. Если входящие соединения уже не ограничены, дополнительное правило не требуется.

Для изменения правил нужны права root/CAP_NET_ADMIN. Учёт изменений хранится в `data/mobile-api-firewall.json`; незавершённая очистка повторяется при следующем выключении или запуске. После выключения API прекращает принимать запросы, даже если порт разрешён другим правилом.

Обеспечьте доступ телефона к выбранному API-порту с учётом сетевой конфигурации сервера. Веб-панель и управление привязками должны оставаться доступны только через доверенный канал.

## Привязка телефона

В веб-панели нажмите «Привязать телефон», затем «Скопировать код». В приложении вставьте его в первое поле подключения или выберите «Привязать через веб-панель». Код содержит адрес API, одноразовый секрет и отпечаток открытого ключа сервера.

Код действует 10 минут и расходуется при первой успешной привязке. Повторное использование отклоняется, включая попытку того же телефона. Новый код выдаётся при каждом нажатии; постоянный ключ сервера при этом сохраняется. Если успешный ответ потерян и приложение не сохранило результат, создайте новый код.

Сервер сохраняет открытый P-256 ключ телефона, приложение — адрес и отпечаток ключа сервера. Закрытый ключ телефона хранится в Android Keystore. Секрет кода сохраняется на сервере в виде хеша; коды, ключи и сессии не записываются в аудит.

При `Unable to resolve host` проверьте адрес, указанный в окне выдачи кода. Домен должен разрешаться на телефоне; для проверки можно использовать IP сервера с портом API. После исправления адреса сохраните настройки и получите новый код: ранее выданный код сохраняет прежний адрес.

В разделе показаны привязанные телефоны. Отзыв удаляет доступ и завершает их потоки/терминалы, даже если отдельная веб-сессия ещё действительна.

## Защита и аудит

API требует подтверждённый ключ телефона независимо от выключателя веб-авторизации. Одноразовые challenge, проверяемые подписи и короткие сессии защищают подключение; включённая веб-авторизация дополнительно требует обычного входа.

Телефон проверяет ключ сервера по отпечатку из локальной привязки. Приложение отклоняет несовпадение ключа до передачи кода и не доверяет произвольным самоподписанным сертификатам. HTTP не принимается API-портом.

Первую привязку через HTTP выполняйте в доверенной сети. Для сети, где возможен перехват или изменение трафика, используйте защищённый канал доступа к веб-панели, например HTTPS или VPN. После привязки соединение приложения шифруется и проверяет сохранённый ключ сервера.

Ключ и сертификат находятся в `data/mobile-api/` с правами 0700 на каталог и 0600 на файлы. Сохраняйте их при переносе или восстановлении сервера. Продление сертификата сохраняет ключ и не требует повторной привязки. Замена самого ключа требует проверки сервера и новой привязки. Изменение порта или HTTPS локальной веб-панели не меняет API-адрес приложения.

В аудит записываются изменения настроек API, ошибки применения, создание кода, привязка и отзыв доступа. Опрос статуса и сохранение без изменений не создают повторных записей. Действия приложения обозначаются как `phone`; для API источник подтверждается сессией устройства. На обычном веб-подключении заголовок `X-Bot4VPS-Client: phone` служит только меткой аудита и не предоставляет доступ. Логин, роль и IP сохраняются в записи автора.

## Структура и обновление

Реализация доступа находится в `ui/web/_internal/device_access/`, локальный файрволл — в `core/_internal/device_access/`. HTTP-обработчик расположен в `ui/web/routers/mobile_access.py`, веб-модуль — в `ui/web/static/js/_internal/device_access/panel.js`.

Перенос исходников не меняет пути данных, настройки, ключи или привязки. При обновлении копируйте оба внутренних пакета целиком вместе с изменёнными файлами интеграции. После их установки прежние модули верхнего уровня можно удалить. Внутренний пакет нужен для запуска панели и при скрытом режиме; для выключения используйте флаг, не удаление исходников.

Резервные команды:

```bash
cd /opt/bot4vps
venv/bin/python -m ui.web._internal.device_access.access pair --name "Мой телефон"
venv/bin/python -m ui.web._internal.device_access.access list
venv/bin/python -m ui.web._internal.device_access.access revoke ID_ТЕЛЕФОНА
```

Для выключения API снимите галочку и сохраните. Для скрытия режима удалите `BOT4VPS_MOBILE_API_PREVIEW` из окружения службы и перезапустите её. Слушатель остановится, правила API будут очищены, ключи и привязки сохранятся.
